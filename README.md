# 電力交易平台刷題系統

台電電力交易平台專業人員資格測驗的練習題庫，涵蓋**科目一（電力系統與電力市場基礎知識）**與**科目二（電力交易平台市場規則）**。

每次進入隨機抽題、選項順序也會打亂；交卷後逐題檢討，錯題下方直接顯示正解、錯誤原因與條文出處。**不記錄任何作答紀錄**，退出即重新抽題。

---

## 快速開始

```bash
npm install
npm run dev
```

打開 http://localhost:3000

正式建置：

```bash
npm run build
npm run start
```

部署到 Vercel：把這個資料夾推到 GitHub，在 Vercel 匯入即可，不需任何環境變數。

## 抽題邏輯

在 `lib/draw.ts`。

1. 勾選「必考題」時，優先放入 `tier: "must"` 的題目，最多佔一份試卷的 **60%**（`lib/draw.ts` 的 `MUST_RATIO`）。題庫的必考題比這個額度多時會隨機輪替，避免每份卷子有一大半完全相同；想每份都塞滿必考題，把 `MUST_RATIO` 改成 `1`。
2. 剩餘名額依 **科目一 3 : 科目二 7** 分配（只考單科時全部給該科）。
3. 同科目內先抽 `core`（重要題），不足再補 `detail`（細節題）。
4. 打亂題序，並逐題打亂選項、換算正解索引。

同一份試卷不會重複出題；題庫少於指定題數時會回傳全部可用題目。

## 新增題目

題庫在 `data/questions/`，一個章節一個檔案。新增題目照 `lib/types.ts` 的 `Question` 介面寫：

```ts
{
  id: "PRD-039",              // 全題庫唯一，慣例 <章節代碼>-<流水號>
  subject: 2,                 // 1 = 科目一、2 = 科目二
  chapter: "交易商品技術規格",  // 結果頁會依此統計弱點
  tier: "must",               // must 必考 / core 重要 / detail 細節
  q: "題幹…",
  options: ["正解…", "誘答…", "誘答…", "誘答…"],
  answer: 0,                  // 正解在 options 中的索引（以「未打亂前」為準）
  explain: "為什麼這是對的，以及錯選常見的原因…",
  source: "管理規範 §14；附件六",
}
```

**要開新章節**時：

1. 在 `data/questions/` 新增檔案，匯出 `Question[]`。
2. 在 `data/index.ts` 裡 `import` 並加進 `QUESTION_BANK`。

開發模式下如果出現重複題號，主控台會印出 `[題庫] 發現重複的題號：…`。

### 慣用的 tier 判準

- `must`（必考）— 條文門檻與核心數字：反應／持續時間、頻率轉折點、服務品質指標級距、容量門檻、價格表、時程表。
- `core`（重要）— 常考觀念與計算邏輯、資源態樣差異、程序步驟。
- `detail`（細節）— 補完整度：單一條文的細部規定、國外市場數據、簡報裡的背景數字。

## 規則更新時怎麼辦

市場規則改版（例如 TPC-MT-v06 上線、跨商品彈性報價正式施行）時：

1. 到 [電力交易平台 — 市場規則](https://etp.taipower.com.tw/web/market_rule) 與 [資料下載](https://etp.taipower.com.tw/web/download) 確認版次。
2. 找出受影響的章節檔案，改寫題目的 `q` / `options` / `answer` / `explain` / `source`。
3. 新制從草案轉為正式規則時，把 `s2-future.ts` 裡對應的題目移到正式章節檔案，並把 `source` 換成正式條文。
